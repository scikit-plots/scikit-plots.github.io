Version 0.5.dev0+git.20261126.fbd8e1a#

November 2026

Build and packaging#

  • Feature The corpus extra requires pypdfium2, which renders PDF pages for PDFReader’s OCR. It has wheels for every supported CPython, including the free-threaded builds. #931

  • Feature docker/env_uv/ holds a uv lock per Python version (3.10 to 3.15) next to the Pipenv and conda environments, generated from requirements/*.txt by .github/scripts/uv_project_from_reqs.py and refreshed by the ci_uv_artifact.yml workflow (one pull request per version); install with uv sync --project docker/env_uv. The env-xeus extra now marks its JupyterLite requirements python_version >= "3.10", the only Pythons they install on. #954

  • Fix Building scikit-plots from a checkout owned by another user (conda-forge, Docker, CI caches) no longer writes safe.directory into your global Git configuration, which also named the wrong directory and so never helped: the version step retries its one git log with git -c safe.directory=<checkout>, only after Git’s “dubious ownership” refusal. The generated Annoy Cython sources now pass cython_generate.py --validate, which compares each output with its template rendered again, and are written atomically. The Meson features module is reinstalled when its content differs or a stale file remains, not only when the source is newer. A source build with numpy installed outside the checkout no longer fails with Include dir ../../venv/... does not exist when the build directory is nested (pip’s build/cp3XY): the numpy include path is now computed relative to the project root, and is absolute unless numpy lives inside the source tree. #909

  • Fix The corpus extra no longer requires pdfminer next to pdfminer.six. The two distributions install the same pdfminer package; installed together they could leave one that cannot import pdfminer.high_level, which PDFReader needs. PDFReader now reports such an install by name, with the commands that repair it, instead of reading with pypdf without a word; if you installed the extra before, run pip uninstall pdfminer pdfminer.six and then pip install pdfminer.six. #930

  • Fix Windows ARM64 wheels build again. The build runners moved to Visual Studio 18.12, whose C++ standard library (MSVC 14.52) refuses a Clang older than 22, and the pinned LLVM 20.1.8 stopped every Windows ARM64 wheel at its first C++ file (error STL1000). LLVM is now 22.1.8, and the build setup compiles one line against the runner’s standard library before building, so a future mismatch stops there with the Clang version required. #948

  • .pre-commit-config.yaml runs action-validator on every GitHub Actions workflow, so an unknown key, a bad needs reference or a glob that matches nothing fails at commit time instead of when the workflow runs; zizmor keeps covering security. #952

Security#

  • Feature scikitplot.cleanprompt: a custom pack pattern that can backtrack catastrophically (nested quantifiers such as ^(a+)+$, overlapping alternations, adjacent quantifiers) is now reported when the pack loads instead of loading silently and stalling a run. Warn is the default; --pattern-risk ignore|warn|refuse (packs, batch, plan, ask, mcp), pattern_risk in a plan file and CLEANPROMPT_PATTERN_RISK tune it per run, team or machine, a pattern can be marked risk: accepted with a risk_reason, and packs --check lists every finding. #864

  • Enhancement cleanprompt flask --debug is now refused on any non-loopback bind, container mode included, and the generated container files publish on 127.0.0.1 only. #864

  • Enhancement scikitplot.cleanprompt: custom pack patterns can now run under a time limit. With the optional regex package installed (pip install "scikit-plots[cleanprompt-timeout]"), --pattern-timeout SECONDS (packs, batch, plan, ask, mcp), pattern_timeout in a plan file, FluentCleanPrompt().pattern_timeout() or CLEANPROMPT_PATTERN_TIMEOUT gives each document one time budget for every custom pattern. A document that runs past it is not cleaned and fails with PatternTimeoutError, naming the pack and kind but never the text; batch continues with the other files. A limit set without regex, or a pattern regex cannot compile, is refused before any document is read. Built-in patterns are unchanged, and doctor reports the new timeout tier. #909

  • Fix scikitplot.cleanprompt: values written with invisible format characters (zero-width spaces and joiners, bidirectional controls, soft hyphens), full-width or other compatibility forms, or Unicode spaces and dashes inside them are now detected and restored exactly as written; previously they were sent unredacted. #864

  • Fix scikitplot.cleanprompt: three disguises that sent a value to the model unredacted are closed. First, an invisible character (a zero-width space or joiner, a soft hyphen, a bidirectional control) inside a variable name or a code identifier no longer hides the value it names, as in export DB_PASS<ZWSP>WORD=... in shell, .env, JavaScript, R, SQL and Python files; the same holds inside a JSON string value, such as an e-mail address. The file’s structure and its exact round trip are unchanged. Second, an e-mail address with one non-ASCII letter anywhere in it is no longer missed whole: an accented local part or domain, an address written in another script, or one starting with a look-alike letter from another script. Addresses may hold letters, digits and combining marks of any script, as internationalised addresses and domains allow. Third, a letter or digit of another script that looks like an ASCII one (a Cyrillic A in an AWS access key, a Cyrillic a in a URL) no longer hides the value or cuts it short: detection reads it as the ASCII character it imitates, from a table generated from the Unicode confusables data. #909

scikitplot.agent#

  • Feature New submodule scikitplot.agent: bounded, audited tool use. Agent runs a goal with a caller-supplied planner (a model adapter or a rule) that returns a Decision (call a Tool, or finish); the runtime alone decides whether an action runs, through five gates in order: Validation (the tool’s JSON Schema, a declared subset checked against jsonschema), Permissions and Scope (Policy, least privilege by default: read tools without scopes only), Budget (Limits: max_steps, which ends every run, tool calls, cost, tokens the planner must report, running time) and Approval (write and external tools need a person’s Approval, bound to the digest of the exact action and re-checked at resume). A denied action is the step’s outcome, not an exception. Every decision, denial, approval and tool call is written to a hash-chained audit trail (MemoryAuditSink, JsonlAuditSink, verify_audit), and the RunState is saved after every step (MemoryStore, JsonFileStore), so a paused or crashed run resumes; a non-idempotent call in flight at a crash is not repeated. Standard library only. #865

  • Feature A planner can keep a plan in the run: Decision.act and Decision.finish take plan= (the whole list of PlanItem, each pending, in_progress, done or dropped), and RunState.plan is the plan of the last decision that carried one, saved, audited and resumed with the decisions. A change that removes an item instead of marking it dropped, or alters a done or dropped item, fails the run with invalid_decision, at most one item may be in_progress, and a saved state whose plan history breaks a rule is refused at load. A decision without plan= is written exactly as before, so existing states and audit trails are unchanged. Large tool results can be kept out of the run state: Agent(artifacts=..., offload_results_over=N) stores a result whose canonical JSON exceeds N bytes in a content-addressed MemoryArtifactStore or DirectoryArtifactStore and records only Step.result_ref (digest and size); the digest is the audited result digest, reads verify it, and a run without a store saves exactly what it saved before. delegate(name, child_agent, max_steps=...) runs another agent as a tool inside the parent’s budget: the delegate has the strongest effect and every scope of the child’s tools, so the parent’s gates and approval decide it; the child’s limits are capped by what the parent has left and its spend is charged to the parent; it writes to the parent’s audit trail under a run id derived from the call, linked by a subrun record. evaluate_audit verifies an audit trail and reports, per run and over top-level runs, how runs ended, decisions, tool calls, denials by code, failures, approvals, sub-runs, plan changes, tokens, cost and wall time. #906

  • Feature WorkflowGraph writes a known order of steps down instead of a planner: Task nodes call one tool, FanOut nodes call several – one audited step per branch (mode="ordered") or one step that runs every branch at the same time (mode="concurrent"), judged by the gates as its branches together and joined in declared order – Finish nodes answer, and Edge objects choose the next node, optionally on a condition. Results are folded into named channels by reducers (replace, append, extend, add, merge or a function). graph.tools() and graph.planner() drive an ordinary Agent, so every call still passes the five gates and is audited; WorkflowGraph.sequence(...) builds a straight line. A graph is checked when it is built – every node reachable, a Finish reachable from every node, every loop through a node with max_visits and its on_exhausted exit not leading back – so every graph that can be built terminates. The planner replays the recorded steps at each decision, so resume needs no new state, the state schema is unchanged, and a state the graph did not produce is refused with WorkflowError; graph.replay(state) returns the position and WorkflowView.digest() its digest. #909

WordChunker honours include_offsets (False by default: no span), and SemanticChunker with include_offsets=False reports (0, 0). An overlap chunk’s context includes a unit min_length dropped inside it. An unpinned embedding model’s cached vectors were served after an upstream change of the model, and the embedding cache grew without bound. With regex installed, SemanticChunker and WritingSystemAdapter therefore dispatch each span to its script’s strategy, so their chunks change: Chinese without jieba becomes one chunk per character, and Arabic, Hebrew, Devanagari, the Dravidian scripts and others use their own strategies. Before, with lxml one such page raised lxml.etree.XMLSyntaxError and ended the whole archive, while without lxml the page was skipped. Hidden parts are now judged below the pattern’s fixed prefix (so docs/.notes/*.md reads the folder it names), unsupported types are skipped for both, and a pattern whose matches are all skipped logs one warning with the counts by reason. #965

  • Fix PDFReader reads rotated text as words with its default pdfminer backend. A vertical chart label used to come out one character per line, reversed at 90 degrees, so years and units were unsearchable (“2015” as 5 1 0 2). Text boxes whose every character is rotated are now regrouped into lines in writing order, at any angle; upright text and its order are unchanged. PDFReader(pdfminer_rotated="pdfminer") keeps pdfminer.six’s own lines, for comparing with it. #969

  • Fix XMLReader reads each text node once by default. Its old default, block_xpath=".//*", took the text of every element including its descendants, so a TEI, JATS or DocBook file came out several times over (a TEI file’s title four times). The new default, block_xpath=None, reads the document’s text blocks: the outermost elements that hold text themselves, in document order, with inline markup kept inside its word (Elementar<hi>form</hi>) and empty elements such as <lb/> read as word breaks. An explicit block_xpath, ".//*" included, keeps its meaning. #971

HTML comments are removed before tags, so a < inside a comment no longer leaves comment text behind. Every chunk records the codec used in its encoding metadata. scikitplot.memmap#

  • Fix An array from MemoryMap.as_numpy_array stays valid after close() (including the with block exit): the mapping now exports its bytes through the buffer protocol and unmaps only when the last view is released. close() from another thread likewise defers the unmap until the end of a running read, write, msync, mlock or munlock; mprotect refuses (BufferError) to remove any protection bit while a view is alive or such an operation is running; and a mapping without PROT_READ exports nothing and refuses read. Each of these used to crash the interpreter (SIGSEGV).

scikitplot.rank_bm25#

  • Feature ScoreCalibrator turns BM25 scores into probabilities of relevance fitted on labelled (query, document) pairs, by Platt scaling ("sigmoid", the default) or isotonic regression ("isotonic"), with the results of scikit-learn’s sigmoid calibration and IsotonicRegression and without needing scikit-learn. fit requires the query of every pair and the population the pairs were drawn from; require_held_out refuses evaluation queries that were used to fit (they are kept only as SHA-256 digests), a fit that would reverse the ranking raises, and shift_prior moves a calibrator to a population with another share of relevant documents by the Bayes prior correction. to_dict and from_dict store it as JSON. #906

  • Efficiency BM25Okapi, BM25L and BM25Plus score from contributions computed once per index (on the first query, or by the new prepare()) instead of re-evaluating the formula for every document on every query: get_top_ids on 200 000 documents went from about 600 ms to about 2.5 ms per query. Results are bit-identical to the reference evaluation for every recipe, including ties and duplicate and unknown query terms. A new backend argument ("auto", the default, "numpy", "numba" or "reference") chooses how the sums run; "auto" uses Numba when it is installed and NumPy otherwise, and every backend returns the same values, so identity does not depend on it.   • Fix BM25Okapi, BM25L and BM25Plus no longer score an empty document NaN (with a RuntimeWarning) when b=1. An empty document holds no query term, so it now scores the recipe’s absent-term value for every b in [0, 1]: 0 for BM25Okapi and the delta lower bound for BM25L and BM25Plus, the same as a non-empty document lacking every query term. Scores of non-empty documents are unchanged bit for bit. The recipes are now okapi-epsilon-floor/2, bm25l-delta/2 and bm25plus-delta/2, so identity tells indexes built before and after the change apart. #909

  • API Change BM25Okapi.load, BM25L.load and BM25Plus.load now verify what they load before rebuilding the index, and refuse with a ValueError naming the cause: a generation of another scorer (load it with BM25Okapi), one built with an earlier version of the formula or an unknown recipe (rebuild it from the corpus), a parameter that is missing, unknown or outside its domain (a persisted b=7 is no longer scored), or metadata whose recorded identity does not match the recipe, analyzer and parameters it declares. Generations of schema bm25-index/1 are no longer read: every one was written with a previous recipe version, so rebuild those indexes with this version. #909
