### Security[#](#security "Link to this heading")

* Feature `scikitplot.cleanprompt`: a custom pack pattern that can backtrack
  catastrophically (nested quantifiers such as `^(a+)+$`, overlapping
  alternations, adjacent quantifiers) is now reported when the pack loads
  instead of loading silently and stalling a run. Warn is the default;
  `--pattern-risk ignore|warn|refuse` (`packs`, `batch`, `plan`,
  `ask`, `mcp`), `pattern_risk` in a plan file and
  `CLEANPROMPT_PATTERN_RISK` tune it per run, team or machine, a pattern can
  be marked `risk: accepted` with a `risk_reason`, and `packs --check`
  lists every finding. [#864](https://github.com/scikit-plots/scikit-plots/pull/864)
* Enhancement `cleanprompt flask --debug` is now refused on any non-loopback bind,
  container mode included, and the generated container files publish on
  `127.0.0.1` only. [#864](https://github.com/scikit-plots/scikit-plots/pull/864)
* Enhancement `scikitplot.cleanprompt`: custom pack patterns can now run under a time
  limit. With the optional `regex` package installed
  (`pip install "scikit-plots[cleanprompt-timeout]"`), `--pattern-timeout
  SECONDS` (`packs`, `batch`, `plan`, `ask`, `mcp`),
  `pattern_timeout` in a plan file, `FluentCleanPrompt().pattern_timeout()`
  or `CLEANPROMPT_PATTERN_TIMEOUT` gives each document one time budget for
  every custom pattern. A document that runs past it is not cleaned and fails
  with `PatternTimeoutError`, naming the pack and kind but never the text;
  `batch` continues with the other files. A limit set without `regex`, or
  a pattern `regex` cannot compile, is refused before any document is read.
  Built-in patterns are unchanged, and `doctor` reports the new `timeout`
  tier. [#909](https://github.com/scikit-plots/scikit-plots/pull/909)
* Fix `scikitplot.cleanprompt`: values written with invisible format characters
  (zero-width spaces and joiners, bidirectional controls, soft hyphens),
  full-width or other compatibility forms, or Unicode spaces and dashes inside
  them are now detected and restored exactly as written; previously they were
  sent unredacted. [#864](https://github.com/scikit-plots/scikit-plots/pull/864)
* Fix `scikitplot.cleanprompt`: three disguises that sent a value to the model
  unredacted are closed. First, an invisible character (a zero-width space or
  joiner, a soft hyphen, a bidirectional control) inside a variable name or a
  code identifier no longer hides the value it names, as in
  `export DB_PASS<ZWSP>WORD=...` in shell, `.env`, JavaScript, R, SQL and
  Python files; the same holds inside a JSON string value, such as an e-mail
  address. The file’s structure and its exact round trip are unchanged.
  Second, an e-mail address with one non-ASCII letter anywhere in it is no
  longer missed whole: an accented local part or domain, an address written
  in another script, or one starting with a look-alike letter from another
  script. Addresses may hold letters, digits and combining marks of any
  script, as internationalised addresses and domains allow. Third, a letter
  or digit of another script that looks like an ASCII one (a Cyrillic `A`
  in an AWS access key, a Cyrillic `a` in a URL) no longer hides the value
  or cuts it short: detection reads it as the ASCII character it imitates,
  from a table generated from the Unicode confusables data. [#909](https://github.com/scikit-plots/scikit-plots/pull/909)

### scikitplot.agent[#](#scikitplot-agent "Link to this heading")

* Feature New submodule `scikitplot.agent`: bounded, audited tool use. `Agent`
  runs a goal with a caller-supplied planner (a model adapter or a rule) that
  returns a `Decision` (call a `Tool`, or finish); the runtime alone
  decides whether an action runs, through five gates in order: Validation
  (the tool’s JSON Schema, a declared subset checked against `jsonschema`),
  Permissions and Scope (`Policy`, least privilege by default: `read`
  tools without scopes only), Budget (`Limits`: `max_steps`, which ends
  every run, tool calls, cost, tokens the planner must report, running time)
  and Approval (`write` and `external` tools need a person’s
  `Approval`, bound to the digest of the exact action and re-checked at
  resume). A denied action is the step’s outcome, not an exception. Every
  decision, denial, approval and tool call is written to a hash-chained
  audit trail (`MemoryAuditSink`, `JsonlAuditSink`, `verify_audit`),
  and the `RunState` is saved after every step (`MemoryStore`,
  `JsonFileStore`), so a paused or crashed run resumes; a non-idempotent
  call in flight at a crash is not repeated. Standard library only. [#865](https://github.com/scikit-plots/scikit-plots/pull/865)
* Feature A planner can keep a plan in the run: `Decision.act` and
  `Decision.finish` take `plan=` (the whole list of `PlanItem`, each
  `pending`, `in_progress`, `done` or `dropped`), and
  `RunState.plan` is the plan of the last decision that carried one, saved,
  audited and resumed with the decisions. A change that removes an item
  instead of marking it `dropped`, or alters a `done` or `dropped` item,
  fails the run with `invalid_decision`, at most one item may be
  `in_progress`, and a saved state whose plan history breaks a rule is
  refused at load. A decision without `plan=` is written exactly as before,
  so existing states and audit trails are unchanged.
  Large tool results can be kept out of the run state:
  `Agent(artifacts=..., offload_results_over=N)` stores a result whose
  canonical JSON exceeds `N` bytes in a content-addressed
  `MemoryArtifactStore` or `DirectoryArtifactStore` and records only
  `Step.result_ref` (digest and size); the digest is the audited result
  digest, reads verify it, and a run without a store saves exactly what it
  saved before.
  `delegate(name, child_agent, max_steps=...)` runs another agent as a tool
  inside the parent’s budget: the delegate has the strongest effect and every
  scope of the child’s tools, so the parent’s gates and approval decide it;
  the child’s limits are capped by what the parent has left and its spend is
  charged to the parent; it writes to the parent’s audit trail under a run id
  derived from the call, linked by a `subrun` record. `evaluate_audit`
  verifies an audit trail and reports, per run and over top-level runs, how
  runs ended, decisions, tool calls, denials by code, failures, approvals,
  sub-runs, plan changes, tokens, cost and wall time. [#906](https://github.com/scikit-plots/scikit-plots/pull/906)
* Feature `WorkflowGraph` writes a known order of steps down instead of a planner:
  `Task` nodes call one tool, `FanOut` nodes call several – one audited
  step per branch (`mode="ordered"`) or one step that runs every branch at
  the same time (`mode="concurrent"`), judged by the gates as its branches
  together and joined in declared order – `Finish` nodes answer, and
  `Edge` objects choose the next node, optionally on a condition. Results
  are folded into named channels by reducers (`replace`, `append`,
  `extend`, `add`, `merge` or a function). `graph.tools()` and
  `graph.planner()` drive an ordinary `Agent`, so every call still passes
  the five gates and is audited; `WorkflowGraph.sequence(...)` builds a
  straight line. A graph is checked when it is built – every node reachable,
  a `Finish` reachable from every node, every loop through a node with
  `max_visits` and its `on_exhausted` exit not leading back – so every
  graph that can be built terminates. The planner replays the recorded steps
  at each decision, so resume needs no new state, the state schema is
  unchanged, and a state the graph did not produce is refused with
  `WorkflowError`; `graph.replay(state)` returns the position and
  `WorkflowView.digest()` its digest. [#909](https://github.com/scikit-plots/scikit-plots/pull/909)

### scikitplot.memmap[#](#scikitplot-memmap "Link to this heading")

* Fix An array from `MemoryMap.as_numpy_array` stays valid after `close()`
  (including the `with` block exit): the mapping now exports its bytes
  through the buffer protocol and unmaps only when the last view is released.
  `close()` from another thread likewise defers the unmap until the end
  of a running `read`, `write`, `msync`, `mlock` or `munlock`;
  `mprotect` refuses (`BufferError`) to remove any protection bit while a
  view is alive or such an operation is running; and
  a mapping without `PROT_READ` exports nothing and refuses `read`. Each
  of these used to crash the interpreter (SIGSEGV).

  Threads may share one `MemoryMap` on free-threaded Python too: its
  open/closed state, export count and protection flags change under a lock
  of the mapping (a `PyMutex`; nothing with the GIL, which already
  serialised them), so a view or a method never starts on a closed mapping
  and the region is unmapped once, after the last view. Without it, threads
  exporting views lost counts: `close()` left the region mapped, or
  unmapped it under a live view (SIGSEGV). [#865](https://github.com/scikit-plots/scikit-plots/pull/865)

### scikitplot.rank\_bm25[#](#scikitplot-rank-bm25 "Link to this heading")

* Feature `ScoreCalibrator` turns BM25 scores into probabilities of relevance fitted
  on labelled (query, document) pairs, by Platt scaling (`"sigmoid"`, the
  default) or isotonic regression (`"isotonic"`), with the results of
  scikit-learn’s sigmoid calibration and `IsotonicRegression` and without
  needing scikit-learn. `fit` requires the query of every pair and the
  population the pairs were drawn from; `require_held_out` refuses
  evaluation queries that were used to fit (they are kept only as SHA-256
  digests), a fit that would reverse the ranking raises, and
  `shift_prior` moves a calibrator to a population with another share of
  relevant documents by the Bayes prior correction. `to_dict` and
  `from_dict` store it as JSON. [#906](https://github.com/scikit-plots/scikit-plots/pull/906)
* Efficiency `BM25Okapi`, `BM25L` and `BM25Plus` score from contributions computed
  once per index (on the first query, or by the new `prepare()`) instead of
  re-evaluating the formula for every document on every query: `get_top_ids`
  on 200 000 documents went from about 600 ms to about 2.5 ms per query.
  Results are bit-identical to the reference evaluation for every recipe,
  including ties and duplicate and unknown query terms. A new `backend`
  argument (`"auto"`, the default, `"numpy"`, `"numba"` or
  `"reference"`) chooses how the sums run; `"auto"` uses Numba when it is
  installed and NumPy otherwise, and every backend returns the same values, so
  `identity` does not depend on it. Numba is imported only when the compiled
  backend is first used, the compiled kernel is cached on disk, and
  `SCIKITPLOT_RANK_BM25_DISABLE_NUMBA=1` forces NumPy. A subclass that
  overrides the scoring formula keeps the previous evaluation. `save` writes
  generations of schema `bm25-index/2`: the postings as `.npy` arrays
  whose SHA-256, dtype and shape `index.json` records, instead of every
  document’s term counts in the JSON. `load` refuses an array that does not
  match, reads with `allow_pickle=False`, recomputes the contributions
  exactly, and accepts `mmap_mode="r"`; on 100 000 documents a generation
  went from 173 MB to 82 MB and loading plus a first query from 4.2 s to
  0.6 s. [#906](https://github.com/scikit-plots/scikit-plots/pull/906)
* Fix `BM25Okapi`, `BM25L` and `BM25Plus` no longer score an empty document
  `NaN` (with a `RuntimeWarning`) when `b=1`. An empty document holds no
  query term, so it now scores the recipe’s absent-term value for every `b`
  in `[0, 1]`: `0` for `BM25Okapi` and the `delta` lower bound for
  `BM25L` and `BM25Plus`, the same as a non-empty document lacking every
  query term. Scores of non-empty documents are unchanged bit for bit. The
  recipes are now `okapi-epsilon-floor/2`, `bm25l-delta/2` and
  `bm25plus-delta/2`, so `identity` tells indexes built before and after
  the change apart. [#909](https://github.com/scikit-plots/scikit-plots/pull/909)
* API Change `BM25Okapi.load`, `BM25L.load` and `BM25Plus.load` now verify what they
  load before rebuilding the index, and refuse with a `ValueError` naming
  the cause: a generation of another scorer (`load it with BM25Okapi`), one
  built with an earlier version of the formula or an unknown recipe (rebuild
  it from the corpus), a parameter that is missing, unknown or outside its
  domain (a persisted `b=7` is no longer scored), or metadata whose recorded
  `identity` does not match the recipe, analyzer and parameters it declares.
  Loading with the `BM25` base class raises `TypeError`. Generations of
  schema `bm25-index/1` are no longer read: every one was written with a
  previous recipe version, so rebuild those indexes with this version. [#909](https://github.com/scikit-plots/scikit-plots/pull/909)

* Feature `tools/maint_tools/security_review.py` prints the S1 to S8 security
  review of a change (secrets, dependencies, code execution, network, file
  writes, untrusted parsing, CI and build files, weakened tests) as a table
  with each hit’s file and line, and the workflow “CI Security Review” runs it
  on every pull request into the job summary. A hit is a place to look, not a
  verdict; the job fails only when a credential pattern is added, and never
  prints the matched value. [#940](https://github.com/scikit-plots/scikit-plots/pull/940)
* Fix `tools/maint_tools/generate_usage_skills.py` loads its renderer
  (`scikitplot/_api_listing.py`) from its own checkout by file path instead
  of importing an installed scikit-plots, so its golden tests run on every
  Python with nothing installed and skills are always rendered by the tree
  they describe. [#944](https://github.com/scikit-plots/scikit-plots/pull/944)
* The usage skills of the `scikitplot` Claude plugin no longer ship a frozen
  `references/API.md` per module (1,331 lines removed). Each skill tells the
  assistant to read the API of the installed version: `python -m scikitplot
  api <module>` for every name at once, and on any release `__all__`,
  `help()` and `inspect.signature`, which are the source of truth if the
  two differ. The example name in each skill is now the first one with a
  call signature, so every command in every skill runs as written (before,
  eight skills named a constant or a compiled class). [#943](https://github.com/scikit-plots/scikit-plots/pull/943)
