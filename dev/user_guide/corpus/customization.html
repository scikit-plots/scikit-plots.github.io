Customization#

Corpus has multiple extension layers. Choose the narrowest one that solves the problem; do not replace the whole builder when a single stage is custom.

Reader-level extractor#

DocumentReader.custom_extractor is the lowest-friction escape hatch for a single reader instance. Common invocation, kwargs forwarding, output normalization and exception wrapping are centralized by DocumentReader.

Builder factories#

BuilderFactories is the construction policy used directly by CorpusBuilder. FactoryCorpusBuilder remains a compatibility facade for code that already uses it. The native builder seam is preferred for new code because every ingestion branch consults the same factory object.

Factories are available for:

  • reader_factory

  • chunker_factory

  • filter_factory

  • downloader_factory

  • normalizer_factory

  • enricher_factory

  • embedding_engine_factory

Reader/filter/downloader factories apply through the builder’s central _make_*/_get_* seams, so archive members and downloaded files do not bypass them.

from scikitplot.corpus import BuilderFactories, CorpusBuilder

def reader_factory(source, *, chunker=None, **kwargs):
    from scikitplot.corpus import DocumentReader
    return DocumentReader.create(source, chunker=chunker, **kwargs)

builder = CorpusBuilder(
    factories=BuilderFactories(reader_factory=reader_factory)
)

The factory container is validated at construction time, while the factories themselves stay lazy. This keeps ordinary CorpusBuilder construction free from optional model imports. Reader, filter and downloader factories are used for local files, downloaded files and archive members rather than being patched onto one call path after construction.

Chunkers and normalisers by name#

BuilderConfig(chunker="...") and normalizer_steps resolve names through one table, the component registry (ComponentRegistry). The built-in chunkers are sentence, paragraph, fixed_window, word, semantic, recursive, parent_child and structure, each registered with its configuration dataclass; chunker_kwargs are that config’s fields, plus any option the chunker’s constructor takes itself (gensim_dictionary for word), and an unknown key raises TypeError naming the valid ones. normalizer_kwargs maps a step name to that step’s options. A chunker you register becomes reachable by name (from the builder and from plans alike) and is never replaced by a built-in of the same name; any class whose chunk takes extra_metadata runs in the pipeline (ProtocolChunkerBridge). An unknown chunker name or normaliser step raises ValueError when the build starts, before any source is read.

from scikitplot.corpus import BuilderConfig, registry

registry.register_builtins()
registry.build_chunker("sentence", overlap=1).config.overlap  # 1
# registry.register_chunker("mine", MyChunker, config=MyChunkerConfig)
config = BuilderConfig(chunker="sentence", chunker_kwargs={"overlap": 1},
                       normalizer_steps=["unicode", "lowercase"],
                       normalizer_kwargs={"unicode": {"form": "NFKC"}})

An enum option of a chunker config accepts the member or its value (SentenceChunkerConfig(backend="regex")); anything else raises when the config is constructed. registry.snapshot() records each chunker’s config class, and ComponentRegistry.load_from_snapshot restores every built-in.

Chunk spans#

A chunk’s start_char/end_char are its anchor: the region it stands for. Its context_start/context_end (context_span) are the region its text is taken from, which covers the anchor and includes any overlap: for every built-in chunker whose text_is_source_slice is True, chunk.text == source[context_start:context_end]. Overlap, merged and split chunks are slices of the source, not parts re-joined with a space. WordChunker derives its text (tokens, case, stems), so its text_is_source_slice is False and its context span is the region the text came from. A sentence splitter that returns text the source does not contain raises when offsets are enabled. A document built from a chunk spans the chunk’s context (char_start/char_end, with raw_text that slice) and records the anchor in metadata["anchor_span"] when the two differ. An overlap chunk’s context runs from its first overlapped unit to its anchor, so it includes a unit min_length dropped in between.

Spans index the text the chunker split. When multilang preprocessing (NFC, BOM and control-character stripping) changed it, the chunk result’s metadata["span_basis"] is "preprocessed" instead of "input", every document built from it records the same in metadata["span_basis"], and no raw_text is sliced with those spans. A document’s raw_text is its region of the reader’s raw text, and None whenever that region is unknown: text that preprocessing changed, or a reader raw_text that is not the chunked text (HTML or XML markup) unless one chunk covers the whole of it. It is never the whole parent for a chunk that covers only part of it. WordChunker reports offsets only with include_offsets=True; without them its raw_text is the segment it took its tokens from.

from scikitplot.corpus import SentenceChunker, SentenceChunkerConfig

source = "Alpha one. Beta two."
chunk = SentenceChunker(SentenceChunkerConfig(overlap=1, min_length=1)).chunk(source).chunks[1]
chunk.text == source[slice(*chunk.context_span)]  # True: "Alpha one. Beta two."
source[slice(*chunk.anchor_span)]                 # "Beta two."

Recursive and parent-child chunking#

RecursiveChunker cuts a text by a hierarchy of separators (blank line, line, sentence end, space, character) only as far as needed for each piece to fit chunk_size characters (not counting the whitespace around it). ParentChildChunker applies the same rule at two sizes: parents that give context, and children inside each parent that are retrieved. Each parent is followed by its children; a document built from a child carries parent_doc_id, its parent’s doc_id, so a hit on a child can return the parent (children and ancestors traverse them). Neither is a default.

from scikitplot.corpus import BuilderConfig, CorpusBuilder

config = BuilderConfig(chunker="parent_child",
                       chunker_kwargs={"parent_size": 1500, "child_size": 200})
docs = CorpusBuilder(config).build("guide.txt").documents
children = [d for d in docs if d.metadata["chunk_role"] == "child"]

The queries are verbatim sentences, so this measures whether a chunker keeps a sentence and its surroundings together, not semantic retrieval. The guide’s lines are hard-wrapped, so recursive (200) cuts at line ends before sentence ends, which is why it splits so many sentences.

StructureChunker chunks Markdown or reStructuredText by its headings and code blocks (markup is given, never guessed): code blocks are chunks of their own, the prose of each section is split by the recursive rule, and every chunk’s metadata holds heading_path (a tuple of the titles above it, outermost first), section_level and block ("prose", "code", "heading" or "front_matter"); documents built from the chunks carry all three. With include_heading (the default) a heading directly followed by prose begins the context of that prose’s first chunk; any other heading is a chunk of its own, so no heading is lost (unless min_length drops it). Markdown: ATX and setext headings, fenced code, thematic breaks and YAML front matter (front_matter); indented code is prose. reStructuredText: section titles, code-block/code/sourcecode directives and :: literal blocks (a directive such as .. note:: is not one; its body is prose).

from scikitplot.corpus import StructureChunker, StructureChunkerConfig

chunker = StructureChunker(StructureChunkerConfig(markup="rst", chunk_size=500))
chunk = chunker.chunk(text).chunks[0]
chunk.metadata["heading_path"], chunk.metadata["block"]

Custom downloader#

Use CustomDownloader when the transfer itself is special, or provide a downloader_factory when the builder should own a custom download policy. The downloader result is still a DownloadResult, keeping download and reader dispatch separate.

Custom retrieval#

CustomRetrievalIndex accepts a ranking callback (custom_scorer_fn). make_pairwise_ranker builds one from any pairwise function, such as edit_similarity or a cross-encoder, with scikit-learn’s greater_is_better sign convention, and make_levenshtein_ranker ranks by scikitplot.levenshtein similarity with the backend that ran recorded on each hit. The Levenshtein module itself does not import Corpus.

To evaluate any retriever, see Evaluating retrieval and answers.

Custom registries#

CapabilityRegistry is an explicit object. Copy the default registry or build a private one and register CapabilitySpec objects. Registration refuses accidental replacement unless replace=True is explicit.
